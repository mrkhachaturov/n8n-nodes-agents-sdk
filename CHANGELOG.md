#### 0.2.0 — M0B UX realignment (BREAKING)

**Summary:** the three action/builder nodes (`M365SendActivity`, `M365TextMessage`, `M365CardTemplate`) collapse into a single `M365 Agent` action node using n8n-native resource/operation UX. Workflows saved against 0.1.x will not load the superseded nodes and must be rebuilt.

The UX philosophy and refactor rationale live in the parent `n8n-workflows` workspace (not in this package) — a published community package ships only `dist/` + `package.json` per manifest §14, so in-package links to `docs/rkstack/` would 404 for any installed user. The two relevant parent-workspace docs (for contributors with the parent repo checked out) are `docs/rkstack/manifests/n8n-node-manifest.md` (n8n UX manifest) and `docs/rkstack/plans/2026-04-17-n8n-nodes-m365-agents-m0b-refactor-plan.md` (this refactor plan).

**New**
- `M365 Agent` action node with resources `Message` / `Card` / `Invoke Response` and operations per resource. Subtitle shows `operation: resource` on the canvas.
- `Conversation Source` Simple / Advanced toggle: `From Envelope` (default, reads the item's `conversationReference`) vs `Specify Manually` (structured fields for proactive sends).
- `M365 Agent Trigger` gains a `Response Mode` parameter (`Immediate` / `Wait For Response Node`) needed for invoke flows.
- Codex metadata (`.node.json`) for both nodes — category: Communication.

**Removed (superseded)**
- `M365SendActivity` — replaced by `M365 Agent` (resource: Message / Card, operation: reply / send / update / delete / replyInThread).
- `M365TextMessage` — replaced by `M365 Agent` (resource: Message, operation: send / reply / update, Text field).
- `M365CardTemplate` — replaced by `M365 Agent` (resource: Card, operation: send).

Source files and their unit tests are removed outright in 0.2.0 (the package is not widely deployed, so a one-cycle deprecation window is unnecessary).

**Changed**
- `usableAsTool` policy: OFF on the `M365 Agent` action (side-effecting — manifest §10.7) and OFF on the Trigger (triggers are not tools — manifest §10.3). 0.1.x had the flag on the builders (correct for pure-builder semantics) and on the Trigger (incorrect); the M0B refactor removes it from the consolidated node and the Trigger.

**Migration**
1. Note your existing nodes' configuration.
2. Upgrade to 0.2.0.
3. Delete the old nodes from each workflow; add a single `M365 Agent` node.
4. Pick resource + operation, choose `Conversation Source: From Envelope` for reply / update / delete flows, fill Text / Card Template, save.
5. Re-activate the workflow.

No automatic migration is provided — by design (sole user, breaking was acceptable).

#### 0.1.3

- fix(builders): `M365TextMessage` and `M365CardTemplate` now preserve all ancillary fields from the input item and overwrite only `activity`. Previous behavior used `mergeEnvelope`, which returned `{conversationReference, activity}` only — dropping workflow state (e.g. `teamsMessageId`, `threadMessage`) carried through earlier nodes and breaking downstream expressions in multi-step bot paths.
- docs: README rewritten as a public package reference (nodes table, install + queue-mode caveats, quick-start echo bot, envelope contract, development/release workflow). `M365CardTemplate` description now points at `https://adaptivecards.microsoft.com/designer`, explains the Sample Data Editor, and notes that `[Parsing] Unknown property` warnings on `Action.Submit.data` custom keys are harmless designer-side false positives.
